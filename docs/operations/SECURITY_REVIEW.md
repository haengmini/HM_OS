# HM OS 보안 점검 — 2026-10-29

## 범위와 한계

이번 점검은 의존성 감사, 인증·세션·채팅·터미널·파일 경계의 소스 검토, 합성 데이터 회귀 테스트와 로컬 브라우저 E2E를 대상으로 한다. 정식 침투시험이나 무취약 보증은 아니다. 실제 개인 파일, PIN, 토큰, 대화·감사 로그 원문을 검사 자료로 수집하지 않았다.

GitHub 소스 반영과 운영 서비스 적용은 별도다. 운영 중인 API는 재설치·빌드·재시작 전까지 기존 코드일 수 있다. 운영 데이터·자격증명·네트워크 경계를 바꾸지 않으며 배포에는 별도 사용자 승인이 필요하다.

## 의존성

초기 `npm audit` 결과는 높음 8건, 보통 4건, 낮음 6건이었다. 호환 가능한 업데이트를 적용하고 직접 의존성의 최소 버전을 Fastify 5.12.7, Vite 6.4.5, Vitest 5.0.5, PM2 7.1.1로 올렸다. 잠금 파일의 하위 의존성도 함께 갱신했다. `npm audit fix --force`나 보안 검사 임계값 완화는 사용하지 않았다.

현재 전체 의존성 감사에는 **낮음 4건**이 남는다. 모두 `vite-plugin-pwa → workbox-build → @rollup/plugin-node-resolve → deepmerge` 빌드 도구 경로다. 프로덕션 의존성만의 감사 결과와 전체 개발·운영 도구 감사 결과를 혼동하지 않는다. PM2는 package.json상 개발 의존성이지만 운영에 사용하는 도구이므로 전체 감사 대상에서 제외하지 않는다.

[GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4)는 확인 시점에 공식 수정 버전이 없었다. 오래된 PWA 플러그인으로 강제 다운그레이드하거나 영향을 알 수 없는 과거 deepmerge 버전으로 내려 경고를 숨기지 않는다.

대신 루트 `npm run build`는 `scripts/build-secure.mjs`를 통해 `NODE_OPTIONS=--disable-proto=throw`를 자식 프로세스까지 전달한다. 실제 설치된 deepmerge에 합성 prototype-poisoning 입력을 넣어 무방어 상태의 반환 객체 오염과 방어 상태의 차단을 확인했다. `npm run test:security`가 차단 회귀 검사를 수행한다. PWA 생성도 이 설정으로 빌드 검증한다.

이 방어는 upstream 패키지의 모든 취약점을 패치했다는 뜻이 아니다. 공식 패치나 의존성 제거가 가능해지면 재평가한다. 이 저장소는 루트 빌드 명령을 지원 경로로 사용한다. 워크스페이스의 Vite를 직접 실행하면 루트 방어 래퍼를 거치지 않는다.

CI는 기존 `npm audit --audit-level=high`를 유지하고 프로덕션 의존성의 `npm audit --omit=dev --audit-level=low`, 통합 테스트, 보안 회귀 검사를 추가한다. 낮음 경고를 숨기는 audit 예외 목록은 두지 않는다.

## 브라우저 대화와 감사 로그

HermesChat은 대화를 React 메모리에만 유지하며 평문 localStorage 저장·복원을 하지 않는다. `hm-os-chat-preview`라는 과거 키는 앱 시작 시 PIN 인증 전에도 제거한다. 대화창을 닫거나 앱을 새로 열면 해당 UI의 대화는 사라진다. 이는 Hermes 서버 측 이력을 삭제하는 기능이 아니다. 이미 열려 있는 과거 앱은 새 빌드로 갱신해야 정리 코드가 실행된다.

감사 로그의 `sessionId` 필드에는 인증에 재사용할 수 있는 원문 대신 SHA-256 해시를 쓴다. 같은 세션의 이벤트 연관성은 유지하되 로그 자체로 인증할 수 없게 한다. 기존 감사 로그는 임의 삭제·재작성하지 않는다. 배포로 API를 재시작하면 메모리 세션은 무효화되지만, 과거 로그 보존 정책은 별도다.

## 인증·세션·스트림·파일 경계

유효한 세션 쿠키가 있어도 Tailscale 신원·Host가 잘못되면 보호 HTTP API를 거부한다. 신원 검사는
중앙 API 경계에 두고 모든 API 응답에 no-store를 적용한다. 미인증 상태, 잘못된 Host·신원과
정상 세션을 함께 테스트한다.

자동 기기 presence·상태 polling은 idle 활동으로 취급하지 않는다. UI는 신뢰된 사용자 입력에
대해 활동 신호를 제한된 주기로 전송하고 서버는 만료되거나 잠긴 세션을 활동 신호로 되살리지 않는다.

명시적 잠금·로그아웃은 세션 무효화 구독으로 채팅 upstream을 취소하고 PTY를 종료한다. idle·절대
만료도 주기적으로 검사하고 후속 출력 전에 다시 확인한다. 느리거나 끊긴 채팅 연결의 backpressure,
타임아웃, 본문 취소와 리스너 정리를 검증한다. upstream의 내부 URL·상세 예외를 클라이언트로 넘기지 않는다.

파일 서비스는 루트의 실제 경로와 symlink 대상·부모 경로를 검사하며 외부 링크를 통한 읽기·쓰기·
업로드·다운로드·목록 조회를 차단한다. 이동으로 재해석되는 상대 링크와 존재하지 않는 파일 말단도
검사한다. 같은 Linux UID로 파일을 동시에 바꾸는 프로세스의 TOCTOU 경쟁까지 차단하는 OS 샌드박스는
아니다. 이 앱의 소유자 터미널은 여전히 그 Linux 사용자의 원래 권한을 갖는다.

## 검증 명령과 결과

통합된 수정본에서 lint, typecheck, API 테스트 120개, 웹 테스트 16개, 계약 테스트 2개,
통합 테스트 2개, 보안 probe와 빌드, 데스크탑·모바일 E2E 10개가 통과했다. 전체 감사는
높음·보통 0건과 낮음 4건이며, 프로덕션 의존성 감사는 0건이다. GitHub CI 결과는 실제 실행으로
별도 확인하며 운영 배포 완료와 동일시하지 않는다.

```bash
npm ci
npm run lint
npm run typecheck
npm test
npm run test:security
npm run test:integration
npm run build
npm run test:e2e
npm audit --audit-level=high
npm audit --omit=dev --audit-level=low
```

CI의 최종 성공은 GitHub 실행 결과로 확인한다. 로컬 명령의 성공이나 Git push 성공만으로 CI 완료를 선언하지 않는다. 테스트의 파일·대화·PIN 등은 실제 사용자 데이터가 아닌 격리된 합성 fixture다.

## 운영 적용 주의

검증된 소스만 반영하고 기존 미커밋 UI 작업은 보존한다. 실제 적용 전에는 영향받는 API 재시작과 브라우저 갱신, 세션 재인증이 필요함을 사용자에게 알린다. PIN 저장소나 감사 로그, 개인 지식 원문은 GitHub에 올리지 않는다. 보안 수정이 사용자에게 새 sudo 권한을 부여하거나 Tailscale Funnel을 켜는 근거가 되지 않는다.
