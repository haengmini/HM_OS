# Anthropic workshop

## "Prompting 101" May 12

1. Claude 프롬프트의 5대 핵심 요소
영상에서 강조하는 고품질 프롬프트를 만드는 5가지 기본 구성 요소는 다음과 같습니다.

① 작업 설명 (Task Description): Claude의 역할(Persona)과 수행해야 할 구체적인 과업을 1~2문장으로 정의합니다.
② 동적 콘텐츠 (Dynamic Content): Claude가 처리해야 할 데이터, 문서, 이미지 또는 외부에서 가져온 정보를 포함합니다.
③ 상세 지침 (Detailed Instructions): Claude가 문제를 해결할 단계를 단계별(step-by-step)로 안내합니다.
④ 예시 (Examples): Few-shot 방식을 사용하여 Claude에게 원하는 결과물의 형태를 보여줍니다.
⑤ 리마인더 (Final Reminder): 가장 중요한 규칙을 마지막에 다시 한 번 강조합니다.

2. 구조화의 핵심: XML 태그 활용
Claude는 구조화된 정보를 매우 잘 이해합니다. 마크다운보다 경계가 명확하고 토큰 효율성이 좋은 XML 태그 사용을 권장합니다.
예: <user_preferences>, <documents>, <instructions>와 같이 태그를 사용하면 모델이 정보의 영역을 명확히 구분하여 처리합니다.

3. 프롬프트 작성 시 주요 원칙
- 명확한 순서 부여: "먼저 문서를 읽고, 그 다음 스케치를 분석하라"와 같이 수행 순서를 명시해야 합니다.
- 불필요한 정보 제거: 결과에 영향을 주지 않는 정보는 과감히 삭제하여 모델의 주의력이 분산되지 않게 합니다.
- 어조 및 스타일 지정: Claude가 답변할 때의 태도(예: 사실적이고 자신감 있는 어조)를 명시하면 출력 품질이 올라갑니다.

4. 추가 팁: 반복적인 피드백 루프
한 번의 프롬프트로 완벽한 결과를 얻으려 하기보다, 다음의 순환 과정을 통해 완성도를 높이는 것이 중요합니다.

- 초기 결과 생성
- 특정 결함이나 부족한 점 식별
- 제약 사항을 수정하여 프롬프트 보완
- 재실행 및 반복

## "Claude를 위한 프롬프트 엔지니어링 Workshop" Jun 13

1. 프롬프트 구성의 5대 핵심 요소
영상에서는 고품질의 출력을 얻기 위해 반드시 포함해야 할 5가지 요소를 강조합니다.

- Persona (역할 부여): Claude가 어떤 전문가로서 행동해야 하는지 명확히 정의합니다.
- Task Description (작업 설명): 무엇을 수행해야 하는지 구체적이고 간결하게 설명합니다.
- Dynamic Content (외부 데이터): 분석해야 할 텍스트, 코드, 데이터 등을 명확히 구분하여 입력합니다.
- Instructions (지침): 작업을 수행하는 단계별 순서(Step-by-step)를 지시합니다.
- Constraints/Examples (제약 및 예시): 결과물의 형식(표, JSON 등)을 지정하거나, 원하는 출력 형태의 예시(Few-shot)를 제공합니다.

2. 전문가의 노하우: 구조화된 입력 (XML 활용)
영상의 핵심 중 하나는 마크다운보다 XML 태그 사용을 권장하는 것입니다.

이유: XML 태그를 사용하면 모델이 정보의 영역(예: <instructions>, <context>, <documents>)을 더욱 명확하게 구분하여, 정보 혼동을 최소화하고 문맥 파악 능력을 높일 수 있습니다.

3. 프롬프트 최적화 프로세스
영상에서는 한 번에 완벽한 프롬프트를 작성하려 하지 말고, 반복적인 수정(Iterative refinement) 과정을 거치라고 조언합니다.
- Initial Prompt: 기본적인 의도를 포함한 프롬프트 작성
- Evaluation: Claude가 내놓은 결과물에서 부족한 점 확인
- Correction: 부족한 부분을 보완할 상세 지침(Constraint) 추가
- Finalization: 프롬프트를 개선하여 재실행

4. 영상 시청 팁
8분 지점까지: 가장 핵심적인 기초 원칙이 담겨 있으므로, 바쁘시다면 영상의 시작부터 8분 정도까지 시청하는 것만으로도 큰 효과를 볼 수 있습니다.

활용: 영상 내에서 Claude의 시스템 프롬프트를 어떻게 설정하는지, 그리고 복잡한 문서를 어떻게 처리하는지에 대한 실무 예제가 시연됩니다.

## "Building with Claude Workshop" Jun 12

1. 고품질 프롬프트를 위한 5단계 구조
Claude가 복잡한 작업을 정확하게 수행하게 하려면 프롬프트를 다음 5가지 요소로 구성할 것을 권장합니다.

- Role (역할): Claude에게 특정 페르소나를 부여합니다 (예: "너는 숙련된 데이터 분석가야").
- Task (작업): 수행해야 할 핵심 과업을 명확하고 구체적으로 기술합니다.
- Context (맥락): Claude가 작업을 이해하는 데 필요한 배경 정보를 제공합니다.
- Steps (단계별 지침): 복잡한 작업은 단계를 나누어 처리하도록 지시합니다. (Chain-of-thought 유도)
- Constraints/Format (제약 조건 및 형식): 결과물에 대한 형식(표, JSON 등)과 반드시 지켜야 할 규칙을 명시합니다.

2. XML 태그 활용의 중요성
영상에서 매우 강조하는 기술 중 하나는 XML 태그의 사용입니다. 마크다운보다 구조가 명확하기 때문에 모델이 정보를 더 잘 구분할 수 있습니다.

활용 예시:

''' XML
<instructions>
  제공된 문서에서 핵심 내용을 요약하세요.
</instructions>
<documents>
  [여기에 분석할 텍스트를 입력]
</documents>
'''
이점: 모델이 instructions 영역과 documents 영역을 분리하여 인식하므로, 프롬프트의 지시사항이 외부 데이터에 의해 희석되는 현상을 방지할 수 있습니다.

3. 반복적 최적화 (Iterative Refinement)
영상은 "한 번에 완벽한 프롬프트를 쓰려 하지 말라"고 조언합니다.
- 프로세스: 초안 작성 → 결과물 확인 → 오류 분석 → 지침 수정 및 보완 → 재실행.
- 특히 모델이 반복적으로 하는 실수를 발견했다면, 이를 System Prompt나 최종 지침(Final Reminder)에 명시하여 강화하는 것이 중요합니다.

4. 실무자를 위한 팁
- 예시 제공(Few-shot): 원하는 출력 결과물의 예시를 1~2개만 제공해도 모델의 성능이 비약적으로 향상됩니다.
- 불필요한 정보 제거: 모델의 주의력을 분산시키는 불필요한 서술은 제거하고, 간결하고 명확한 문장을 사용하는 것이 좋습니다.
